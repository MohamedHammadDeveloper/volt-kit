# volt-kit

إضافة لـ Claude Code تجمع طريقة عمل كاملة: توثيق في **Vault**، وتخطيط بالمواصفات **Spec-driven**، وبحث في الكود عبر **graphify**، و**منسّق (Orchestrator)** يكتب أوامر الوكلاء ويراقبهم ويراجعهم. تصلح لأي مشروع.

النسخة الإنجليزية: [README.md](README.md)

## التثبيت

```
/plugin marketplace add MohamedHammadDeveloper/volt-kit
/plugin install volt-kit@volt-kit
```

## المتطلبات
- Claude Code وgit (السكربتات بـ `sh` عادي؛ على ويندوز استخدم Git Bash).
- أداة graphify (تُثبَّت منفصلة، غير مرفقة).
- أداة `specify` من [spec-kit](https://github.com/github/spec-kit) (`uv tool install specify-cli`).

## المبدأ الأساسي
**أنت تتكلم مع المنسّق (Orchestrator) فقط.** أي وكيل آخر يبدأه المنسّق ويرجع له هو، ولا يرجع لك أبدًا. قبل أي مهمة خارج صلب الهندسة أو متكررة، المنسّق يراجع `docs/team.md`؛ لو مفيش متخصص مناسب يقترح إنشاء واحد (`/volt-kit:hire`) بدل ما ينفّذها بنفسه.

## البداية السريعة
1. في مشروع جديد: `/volt-kit:kickoff`؛ الجلسة تصبح المنسّق ويسألك سؤالًا واحدًا في كل مرة (النشاط، المستخدمون، المنصات، التقنيات، حجم الفريق، مشروع جديد أم كود قائم، بيئات النشر، اللغات، الأمان والامتثال، نطاق النسخة الأولى، ميزانية الموديلات). يكتب `docs/brief.md` و`docs/volt-kit.config.md`، وبعد موافقتك على خطته يجهّز الـ Vault وتكامل spec-kit وgraphify والدستور وقواعد مفصّلة على تقنياتك ووكلاء ومهارات خاصة بالمشروع و`docs/team.md`.
2. الجلسات التالية: `/volt-kit:resume`.
3. سجّل فكرة (`/volt-kit:idea`)، اكتب مواصفة (`/volt-kit:spec-new` و`/volt-kit:spec-debate`)، وافق عليها، ثم `/volt-kit:build <رقم>`.

## الأوامر
| الأمر | وظيفته |
|---|---|
| `kickoff` | مشروع جديد: مقابلة، brief، إعداد، هيكل، قواعد وفريق مفصّلين |
| `resume` | بداية جلسة لاحقة: يقرأ الحالة ويعرض المعلّق ويصبح المنسّق |
| `status` | جدول تقدّم مع تقدير الوقت |
| `idea` | تسجيل فكرة في الـ Vault بدون بدء شغل |
| `spec-new` / `spec-debate` | مسودة مواصفة / مناظرة بين مخطِّطَين |
| `build <spec>` | كل مراحل مواصفة معتمدة باختباراتها حتى staging |
| `fix` | عيب: إعادة إنتاج، إصلاح، اختبار انحدار، إصدار patch |
| `screens` | صور حقيقية قبل/بعد لموافقتك |
| `ship staging` or `ship prod` | إصدار؛ production بكلمتك الصريحة فقط |
| `rule` | حفظ قاعدة «من الآن» مع السبب وطريقة التطبيق |
| `decide` | تسجيل قرار (ماذا ولماذا والبدائل) |
| `health` | الجراف، الـ Vault مقابل الكود، الإصدارات، قائمة الفريق |
| `hire` (`--update` و`--retire`) | إنشاء أو تعديل أو إنهاء وكيل متخصص ومهاراته |

## الطريقة
- **الـ Vault:** مجلد `docs/` فيه ملاحظة رئيسية بقسم «الشغل الجاري» يُحدَّث بعد كل مهمة، وسجل إصدارات، وملاحظة لكل مواصفة مرقّمة مع مجلد لخططها وعقدها. ممنوع الأسرار.
- **المواصفة أولًا:** لا يُبنى شيء قبل موافقة المالك؛ المواصفة المعتمدة عقد؛ كل سؤال مفتوح معه توصية.
- **المناظرة:** مخطِّط معماري (موديل قوي) ومخطِّط منتج/تجربة (موديل افتراضي) يكتبان بالتوازي ويراجع كل منهما الآخر، ثم تُكتب المسودة.
- **الجراف:** اسأل graphify بأسماء الكود أولًا، وحدّثه بعد أي إضافة أو حذف أو إعادة تسمية.
- **الوكلاء:** قائمة ملفات مسموحة، اختبارات محددة بحد أقصى، توقّف بعد 3 محاولات فاشلة، لا git للوكلاء، موديل مناسب لكل مهمة، وملف عقد بين الباك والفرونت.
- **الإصدار والاختبار:** كل تعديل يرفع الإصدار والـ CHANGELOG؛ staging بموافقة الجلسة، وproduction بكلمة صريحة من المالك؛ اختبارات آخر مواصفة قبل الـ commit، والطقم الكامل مرة واحدة من القائد.
- **الأمان:** صور حقيقية قبل أي تغيير ظاهر؛ الوكلاء لا يقرؤون قيم الأسرار أبدًا.

## المحتويات
مهارات (12)، وكلاء (7)، أوامر (14)، Hooks (تذكير بدء الجلسة، تذكير graphify عند إنشاء ملف جديد، تذكير عند تغيّر الكود دون الـ Vault)، وقوالب.

## الإعداد
ملف `docs/volt-kit.config.md` يحوي اسم المشروع واللغات والموديلات والبيئات. المهارات والوكلاء مكتوبة بالإنجليزية، والمنسّق يرد عليك باللغة التي تحددها.
