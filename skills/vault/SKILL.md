# Vault method

The vault is a plain-Markdown folder (default `docs/`, set in `docs/volt-kit.config.md`), Obsidian-compatible with `[[wikilinks]]`. It is the project's living reference for the owner and for every new session.

**Why:** a reference that is not updated becomes worthless, and a model's context fills up and forgets. The vault keeps the state outside the conversation, so a fresh session (or a new teammate) continues without re-asking.

## Layout
```
docs/
  home.md                  version status + "Current work" + sections map
  versions-log.md          one line per released version, newest first
  decisions.md             owner decisions with dates
  roadmap.md  open-and-deferred.md   (optional) spec status and parked items
  volt-kit.config.md       project settings
  architecture/            AGENT-RULES.md, CONVENTIONS-backend.md, CONVENTIONS-frontend.md
  specs/README.md          index; NN-name.md per spec; NN-name/ folder per spec
  ux-review/<screen>/      designer notes, proposals, screenshots (if UI work)
  private/                 git-ignored; sensitive-but-useful notes, never values
```

## Rules
1. **Update after EVERY task, before saying "done"**, big or small: home note status and "Current work", versions log if a version moved, decisions if the owner decided something, the spec note's status.
2. **Also update during long work**, after each step, not only at the end. **Why:** the owner asked for it because the session context fills up; the vault is the safe copy of progress. The "Current work" section records what finished, what is running, what is waiting for the owner.
3. **One note per numbered spec** plus a folder with the same number for its inputs (planner A/B plans, cross reviews, contract). Numbers are never reused. Every spec note links its folder, its versions-log entry and neighbouring specs.
4. **Short, factual, dated.** ISO dates. Markers in lists: done, in progress, waiting for owner, blocked, parked. Each shipped item has version, commit hash and date.
5. **Never in the vault:** secrets, tokens, passwords, keys, personal data, customer data. Say where a secret lives, never what it is.
6. **Private subfolder:** account lists, access notes (without values), anything sensitive-but-useful go in `docs/private/`, in `.gitignore`. Agents never read it unless the owner points to it.
7. **Scope:** the vault covers the product it was created for. Side projects and demos in the same machine do not write into it unless the owner says so.
8. **Docs travel with the code:** the screen's note, help page or lesson changes in the same change as the screen.
9. Diagrams that mirror code (database, architecture) are regenerated by their script after a change that affects them, not edited by hand.
10. Commit the vault with the task or right after it; only the lead commits, only when the owner allows.

## How to apply
`/volt-kit:health` checks drift between vault and code. Mechanical edits can go to `vault-keeper` (small model) with the facts in the brief. If a fact is missing, ask; do not invent it.
